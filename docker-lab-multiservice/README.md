# Лабораторная работа. Сборка и запуск многоконтейнерного приложения на C

**Тема:** Dockerfile, Docker Compose.

## 1. Цель работы

Организовать сборку многокомпонентного проекта на C в Docker-контейнерах и запуск его частей с помощью Docker Compose.

Программы на C уже написаны, вся инфраструктура сборки (root и дочерние Makefile) прилагается в готовом виде. **Изменять файлы `.c`, `.h` и любые `Makefile` не нужно.** Необходимо написать только конфигурацию Docker: три двухэтапных Dockerfile, файл `compose.yaml` и `.dockerignore`.

## 2. Описание системы

Проект включает три приложения:

- **backend** — HTTP-сервер. В ответ на `GET /` возвращает сообщение с именем сервера.
- **balancer** — принимает HTTP-запросы и по очереди направляет их двум backend-серверам (Round Robin).
- **loadgen** — отправляет запросы балансировщику, измеряет время ответа и записывает результаты в CSV.

В итоговой системе должны работать четыре контейнера: два экземпляра `backend`, один `balancer`, один `loadgen`.

```text
                       Компьютер
                  http://localhost:8080
                           |
                           v
                       balancer
                       порт 8080
                       /       \
                      v         v
               backend-1     backend-2
                порт 9000     порт 9000

                       loadgen
                          |
                          v
                   balancer:8080
                          |
                  результаты в CSV
```

## 3. Структура проекта и зависимости

В выданном архиве находится следующая структура:

```text
c-lab-multiservice/
├── Makefile                 # Готовый, изменять не нужно
├── lib/
│   ├── Makefile             # Готовый, изменять не нужно
│   ├── net.c
│   ├── http.c
│   └── utils.c
├── include/
│   ├── net.h
│   ├── http.h
│   └── utils.h
├── apps/
│   ├── backend/
│   │   ├── Makefile         # Готовый, изменять не нужно
│   │   ├── main.c
│   │   ├── handler.c
│   │   └── handler.h
│   ├── balancer/
│   │   ├── Makefile         # Готовый, изменять не нужно
│   │   ├── main.c
│   │   ├── router.c
│   │   └── router.h
│   └── loadgen/
│       ├── Makefile         # Готовый, изменять не нужно
│       ├── main.c
│       ├── stats.c
│       └── stats.h
└── README.md
```

Общие функции объявлены в `include/` и реализованы в `lib/`. Сборка из `lib/net.c`, `lib/http.c` и `lib/utils.c` даёт **статическую библиотеку** `build/lib/libcommon.a`.

Все три приложения используют эту библиотеку:

```text
     lib/net.c  lib/http.c  lib/utils.c
                  |
                  v
       build/lib/libcommon.a
            /     |     \
           v      v      v
       backend  balancer  loadgen
```

Исходники приложений распределены следующим образом:

| Приложение | Собственные исходники | Результат сборки |
|---|---|---|
| backend | `main.c`, `handler.c` | `apps/backend/backend` |
| balancer | `main.c`, `router.c` | `apps/balancer/balancer` |
| loadgen | `main.c`, `stats.c` | `apps/loadgen/loadgen` |

**Порядок сборки:** сначала общая библиотека, затем приложения. Корневой `Makefile` и дочерние Makefile уже задают этот порядок. Достаточно выполнить `make` из корня проекта.

## 4. Какие файлы необходимо написать

Всего необходимо создать **5 файлов**:

| Файл | Назначение |
|---|---|
| `apps/backend/Dockerfile` | Образ backend |
| `apps/balancer/Dockerfile` | Образ balancer |
| `apps/loadgen/Dockerfile` | Образ loadgen |
| `compose.yaml` | Запуск и настройка четырёх контейнеров |
| `.dockerignore` | Исключение ненужных файлов из контекста сборки |

**Root и дочерние `Makefile` уже готовы — их писать и изменять не нужно.** Внутри Docker-контейнеров сборка тоже выполняется с их помощью: команда `make` в каталоге `lib` собирает библиотеку, а `make` в каталоге приложения — сам исполняемый файл.

### 4.1. Требования к Dockerfile

Для каждого приложения создайте отдельный Dockerfile с **двухэтапной сборкой**:

1. В первом этапе должна выполняться сборка общей библиотеки и соответствующего приложения.
2. Во втором этапе должен находиться только готовый исполняемый файл и необходимые компоненты среды исполнения, без компилятора и инструментов сборки.

Можно использовать образы `gcc:13-bookworm` и `debian:bookworm-slim`.

Общая библиотека и заголовочные файлы находятся вне каталогов отдельных приложений. Это необходимо учесть при выборе контекста сборки Docker.

Внутри этапа сборки компиляция выполняется с помощью готовых Makefile, поэтому в образе сборки должен присутствовать `make`, а до сборки библиотеки и приложения необходимо выбрать соответствующий каталог (`cd`).

### 4.2. Требования к Docker Compose

Опишите сервисы со следующими именами: `backend-1`, `backend-2`, `balancer`, `loadgen`. Два backend должны использовать **один и тот же Dockerfile**, но работать в отдельных контейнерах.

**Порты:**

| Сервис | Порт внутри контейнера | Доступ с компьютера |
|---|---|---|
| `backend-1` | `9000` | Не публиковать |
| `backend-2` | `9000` | Не публиковать |
| `balancer` | `8080` | Опубликовать на порту `8080` |
| `loadgen` | Входящий порт не нужен | Не публиковать |

Внутри сети Docker Compose нужно использовать имена сервисов для обращения к другим контейнерам. Для `loadgen` настройте сохранение CSV в локальном каталоге `results/`. Предусмотрите порядок запуска: сначала backend, затем balancer, затем loadgen.

**Переменные окружения приложений:**

| Сервис | Переменная | Значение |
|---|---|---|
| `backend-1` | `PORT` | `9000` |
| `backend-1` | `SERVER_NAME` | `backend-1` |
| `backend-2` | `PORT` | `9000` |
| `backend-2` | `SERVER_NAME` | `backend-2` |
| `balancer` | `PORT` | `8080` |
| `balancer` | `BACKENDS` | `backend-1:9000,backend-2:9000` |
| `loadgen` | `TARGET_HOST` | `balancer` |
| `loadgen` | `TARGET_PORT` | `8080` |
| `loadgen` | `REQUEST_COUNT` | `1000` |
| `loadgen` | `OUTPUT_FILE` | `/results/result.csv` |

Каталог `/results` контейнера `loadgen` должен соответствовать каталогу `results/` в корне проекта на компьютере.

## 5. Проверка работоспособности

Все проверки выполняются из корня проекта.

### 5.1. Локальная сборка

Выполните `make` и убедитесь, что созданы файлы:

```text
build/lib/libcommon.a
apps/backend/backend
apps/balancer/balancer
apps/loadgen/loadgen
```

Проверьте, что `make clean` удаляет результаты сборки, а последующий `make` снова собирает проект.

### 5.2. Запуск контейнеров

Соберите образы и запустите систему с помощью Docker Compose.

Проверьте состояние контейнеров и журналы `loadgen`. После завершения нагрузки `loadgen` должен завершиться успешно, а другие три контейнера — продолжить работу.

Ожидаемое сообщение в журнале генератора:

```text
Requests: 1000, successful: 1000, failed: 0
```

### 5.3. Работа балансировщика

Выполните несколько HTTP-запросов:

```bash
curl http://localhost:8080/
curl http://localhost:8080/
curl http://localhost:8080/
```

Ответы должны чередоваться между:

```text
Hello from backend-1
Hello from backend-2
```

Первый ответ может принадлежать любому backend, если балансировщик уже обслуживал запросы.

### 5.4. Результаты нагрузки

Проверьте файл `results/result.csv`. В нём должно быть **1001 строка**: заголовок и 1000 результатов запросов. Ожидаемые столбцы:

```csv
request_id,backend,latency_ms,status
```

При отсутствии параллельных запросов ожидается примерно поровну, а для последовательного генератора — по 500 ответов от каждого backend.

### 5.5. Изменение конфигурации

Измените `REQUEST_COUNT` в конфигурации Compose с `1000` на `100` и повторно запустите `loadgen` без пересборки образов. В результирующем CSV должна быть **101 строка** с учётом заголовка.

## 6. Что показать преподавателю

1. Результаты локальной сборки, выполненной готовыми Makefile.
2. Три двухэтапных Dockerfile и файл `compose.yaml`.
3. Работающий балансировщик, чередующий ответы двух backend.
4. CSV-файл с результатами нагрузки и изменение количества запросов без пересборки образов.

**Критерий выполнения:** проект собирается готовыми Makefile, четыре контейнера запускаются, приложения взаимодействуют через сеть Docker Compose, а результаты `loadgen` сохраняются на компьютере.
